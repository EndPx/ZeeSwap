# Automatic unsigned source metadata recovery

The user requested continuous remote service operation. Root observed an ordinary
Base consumer gap after an RPC failure while Native observation remained healthy.
The old automatic recovery authority was intentionally restricted to its original
preuser books and counts. It could not qualify the later unsigned waiting order
and retained quote history. This change adds a separate version 2 Root authority;
it does not relax the original finite purpose or alter Core/indexer engines.

`ROOT_UNSIGNED_AUTOMATIC_SOURCE_METADATA_RECOVERY` binds the current immutable
policy, control epoch/xmin, original activation XID, profile/contracts, original
recorded expiry, unchanged policy limits and exact lifetime/reuse authorization
hashes. The effective service authority has no time expiry only while both actual
immutable SQL grants validate at every state read. A protected Root authority and
configuration select this path; ordinary invocation remains inspect-only.

Every state check requires an inactive or failed financial unit with MainPID zero,
no worker lease, no new admitted-order deposit and at most one strictly unsigned
waiting order. It reuses the reviewed unsigned restart qualification for safe
expired attempts, a reserve-only `AWAITING_FUNDS` order or nonfinancial bound
quotes. Process/native directories and per-settlement Base signer journals must
be absent. This qualification deliberately does not require fresh Base observation
because recovering that stale projection is its purpose. It does not grant a
financial action while source observations are stale.

The original-book projection is used only for eligibility. The actual full books,
held reservations, order terms, financial lineage, immutable service grant pins
and Native checkpoint stay in the raw recovery baseline and must remain unchanged
through collection, SQL publication and original-XID reconciliation. No normalized
financial snapshot is stored or substituted in a metadata proof. The new purpose
supports up to 32 retained historical quotes/admissions and bounded 1,024-row
financial tables; larger or truncated captures fail closed. Version 1 retains its
original counts, 128-row financial bound and policy expiry.

The event collector and publication boundary remain unchanged: at most 500,000
blocks in 1,000-block packets, zero raw SDK events and zero independent logs,
independent canonical boundaries and retained financial anchors, and an actual
fresh final SDK selection with a maximum 5,000-block tail. There is no fabricated
`observedAt`, dense-history bypass or broader historical-readiness claim. Marker,
active admission pointer, exact metadata CAS, durable original-XID intent and ACK
reconciliation retain their original behavior. The legacy inspector/success
labels remain for watchdog compatibility; version 2 authority identifies the new
eligibility semantics explicitly.

Version 2 completion records actual historical quote/admission counts and the
funded-or-active capacity basis. It omits version 1's fixed remaining 1/2/31
values. Actual budgets, history and reservations are preserved; a recovery does
not consume or reset financial capacity. Any deposit, signature, changed books,
new financial process, artifact or unexpected source event stops this path for
review. A live financial worker is never signalled or stopped by this new purpose.
