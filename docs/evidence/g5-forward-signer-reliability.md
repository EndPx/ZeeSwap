A finalized state of NONE is insufficient to wait. The separate lag proof requires this signer's immutable RESERVE journal and authorization, exact calldata, raw keccak, the original successful RPC transaction/receipt, bounded actual fees and its exact `PayoutReserved` event. The receipt must lie above the pinned finalized head. A fresh pinned latest head must cover the receipt and show RESERVED with the exact recipient, amount and deadline. The receipt block must contain the original transaction, and finalized, receipt and latest block anchors must survive canonical rereads. The same latest timestamp is checked again after these reads. Only this proof can produce `BASE_SIGNER_FINALITY_WAIT`; it creates no new authorization, nonce intent, raw transaction or journal write. Missing, contradictory, stale or malformed evidence remains hard. No caller-supplied receipt or new request field authorizes this proof.

The other prospective wait is limited to `subprocess.TimeoutExpired` from an explicitly permitted read operation, while the invocation has performed no new journal mutation, signing or nonce allocation. Python's bounded `subprocess.run` has killed and waited for the direct read child before emitting the packet, and any owned lock must already be released. A timeout after a new typed/auth write or any nonce/transaction intent remains hard. Arbitrary nonzero exits, wrong deployment/network, permission failures, malformed output, unknown failures and outer process timeouts are never reclassified as waits. Existing artifacts from a previous invocation are preserved and are not described as absent.

Both wait protocols bind the canonical request digest, command, forward phase, closed stage/code, clean dedicated exit (75 for completed read timeout; 76 for authenticated reserve lag), and exact no-new-effect flags. The TypeScript adapter requires one matching stderr primary with no cleanup or contradictory packet. A wrong digest, wrong phase, extra field, mismatched exit, signal or lock-release error is hard. Normal reverse FUNDING/COMMIT/SETTLE and refund replies retain their shared transport compatibility; forward waits cannot soften reverse failures.

The forward signer passes its owned flock descriptor to cast children. A surviving child therefore retains the lock after its parent closes its handle, preventing another signer from treating a still-running child as quiescent. This is a lock guarantee, not permission to retry an uncertain signing operation.
