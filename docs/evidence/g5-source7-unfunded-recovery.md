expiry is not its accepted Zcash funding cutoff. The existing normal expiry
transition requires a fresh checkpoint through cutoff+9; this proposed recovery
requires actual complete source scan coverage through at least cutoff+10,
canonical checkpoint rereads and no old-receiver/reference output.

The complete precondition also requires the original isolated 110000-zatoshi
source input still confirmed and unspent, no SDK pending/raw effect, no running
actor or descendant, no retained intent/result and no financial rows or
expenses for the old attempt. An existing, ambiguous or changed original effect
blocks this route. No resend, replacement source, deleted lock/intent or reduced
eight-block funding margin is authorized by the design.

as EXPIRED_UNFUNDED through the normal reservation-release transition. Retain
its quote/order, owner credential, receiver/reference, original cutoff,
funding artifact, diagnostic and audit hashes. Its only monetary bookkeeping

balanced for each event/asset with no principal expenditure or fee debit.
There must be no primary deposit, deposit/obligation, operation/job, Base or
shielded attempt, refund, or other financial authority for that predecessor.

A single successor may then receive a new quote/order, owner, receiver,
reference and normally accepted cutoff, using the same originally approved
source wallet/input, principal and fee limits. The old funding artifact must
remain immutable; the successor uses a distinct authenticated attempt artifact
and append-only history. This is a first source payment for a new quote only
after the old attempt is proved unfunded, not a retry of unknown bytes. A failed
or uncertain transition stays paused rather than creating unlimited attempts.

The shared partition classifier must admit only the exact audited predecessor.
It must continuously reject changed artifacts, unexpected extra IDs, missing or
duplicated reserve/release ledger entries, any old source effect and any second
archived exception. Controller admission, ordinary operator checks, reverse
slots, full barriers and close must use the same rule. Historical recoveries
retain their original exact scopes; this is not a generic expired-row filter or
incident-clear capability.

The old receiver remains scanned. A later deposit, even after expiry, creates
or preserves its real liability and invalidates the no-effect exception. The
run must stop for reconciliation/refund; neither the receiver nor its output
may be excluded to make a boundary pass.
