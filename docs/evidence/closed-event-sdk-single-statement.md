# Closed-event SDK transport: one statement snapshot

The new `envio-closed-event-sdk.ts` transport leaves the executed closed-event IO/core/store unchanged. It uses an exclusively held direct `pg` client. Initialization sets default_transaction_read_only=on, statement_timeout=5000ms and idle_in_transaction_session_timeout=10000ms once, then verifies the actual database, role, privileges and effective read-only context. There is no credential lookup or connection fallback in this module.

Each snapshot executes one parameterized SELECT combining the exact frozen raw SettlementEvent aggregate query with SDK state and current privilege context. PostgreSQL gives all subqueries in this SELECT the same MVCC statement snapshot, replacing the old multi-statement repeatable-read transaction without mixing state and events from separate snapshots. An explicit fence executes one additional SELECT. The raw query remains filtered only by chain, contract and requested block range: no token, event-name or version filter. Overflow1001, the7.9MB aggregate guard, actual8MB JSON bound, unknown-version refusal, checkpoint/generation/revision/freshness validation and true recovery floor are preserved.

Every snapshot/fence checks actual transaction_read_only and default_transaction_read_only, effective5-second statement timeout, restricted Source role/database, no elevated role, no table INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER or schema CREATE privileges, and SELECT on both raw events/state. The caller supplies the original AbortSignal. A stopped/failed statement is awaited and its result cannot be returned after abort; failures poison the transport, with no retry, manual transaction, rollback request or automatic reconnection. The client must not be shared or returned to a transaction pool while this transport is in use.

Tests assert one snapshot query plus one fence query, exact old raw SQL embedding and equivalent old/new results, historical ranges below the true floor, role/DDL/TRIGGER/read-only/timeout refusal, overflow/unknown version/stale state/checkpoint rejection, no retry after errors, original abort behavior and initialization/range limits. No database connection, SQL execution or Source/service operation was performed by the coding agent. Actual Source timing and read-only privilege behavior require operator qualification; this evidence does not claim a throughput improvement measured on Neon.
