# Unarmed market user circle

This new actor is `market-user-circle-20261027-r1`. It does not start G5, alter
old wallets, install a service, allocate capital, create keys or claim browser
wallet signing. Root alone provisions and runs each financial step after the
source collectors' frozen baseline is closed and fresh source, capital and
policy gates pass. Default `enabled:false` returns before any secret/helper or
network access. Local examples under `.deploy-local/market-user-circle-20261027-r1/`
are unresolved placeholders, not a funded configuration.

## Reviewed boundaries

The new public CLI and wrappers adapt the previously unarmed private user-tool
candidate. Historical G4/G5/fixed-fixture guards are unchanged. The native wrapper
inherits the existing full prepared-raw, selected-note, fee, outgoing-decryption
and canonical-receipt verifier. Its new guard accepts only an independently
bound market order. The Base wrapper writes an exclusive nonce/signing intent
and original raw file, and cannot sign again after uncertainty.

Actor source amounts are exactly 100000 zatoshi forward and 1000000 mockUSDC units
reverse. One accepted order per direction, at most two known-expired predecessor
quotes, native fee <=10000 zatoshi, each Base actor transaction <=10000000000000
wei and their actual aggregate <=20000000000000 wei. No mint, operator-native
setup or automatic gas funding exists. Forward delivery must be >=1000000 mock
units. Contract inventory alone does not satisfy application principal books.

## Root provisioning

Create a protected local actor directory and a Linux journal directory ending
in the exact namespace; Linux journal modes are 0700/0600. Use new faucet-funded
keys, or explicitly prove reused identities are outside G5 and all prior
calculations, signatures and journals are closed. Wallet and nonce locks must
be the actual shared identity locks, even for approved historical reuse.
Never copy an existing reverse/refund capital proof to describe setup change.

Required immutable files, all privately pinned by actual raw SHA256:

1. Actor config `user-actor.config.private.json`, initially disabled. Its code pins
   cover the CLI, checker, both new wrappers and the explicitly enumerated reused
   modules. Pin actual Node24, tsx loader and WSL transport (or Linux interpreter).
   WSL distro is Ubuntu-24.04; helper paths must resolve to these repository files.
2. `ROOT_MARKET_ACTOR_APPROVED`: exact caps, origin, actor identities, profile,
   policy, source-closure gate and expiry <=two hours. This is fresh Root authority,
   not an approval generated by the actor. Its `identityProofSha256` uses the
   checker's sorted-key compact JSON digest; other file pins hash raw bytes.
3. `ROOT_MARKET_ACTOR_IDENTITY_CAPITAL_VERIFIED`: actual non-G5 identity paths,
   viewing-key digest, owned shielded UA, Cast account/password path, initial
   nonce, initial zero mock balance, closed journals and zero pending calculations.
   Pin independent read/faucet/identity evidence files. `expectedProvenance` lists
   confirmed Ironwood notes with txid/index/value/height/blockHash/receiver and
   ownChange; require >=110000 zatoshi and no duplicate identity. Native preparation
   independently decrypts and canonically rechecks these notes and rechecks the
   complete actual unspent SDK inventory before calculation.
4. `ROOT_MARKET_USER_PREPARATION_GATES_VERIFIED`: same profile/policy and the
   policy's canonical-audit, capital-allocation and source-identity digests, with
   at least three pinned independent evidence files. Root must actually verify
   the application books, permit and post-collector closure before issuing it.
5. Actual immutable market policy and deployment registry copies. No operator
   profile is edited. Base RPC stays the documented Base Sepolia PublicNode
   endpoint. Public app origin is exactly `https://zeeswap.endpx.cloud`.
6. Native and Base helper configs. Bind their identities to the identity proof,
   exact shared locks, new journal directories, pinned Python/Cast/SDK/readers and
   pinned guard transport back to this CLI and this exact config. No seed is
   placed in browser JavaScript. The wrappers run only as the local Linux user.

Each accepted order also needs a separately Root-issued
`ROOT_MARKET_USER_ORDER_BOUND` file. This binds its original accepted API response,
private capability-file digest, input/output, snapshot digest, original funding
instructions/cutoff, policy/epoch, settlement ID and actor. Its pinned
`ROOT_MARKET_USER_MEMBERSHIP_VERIFIED` evidence must contain the independently
read/decrypted accepted quote's actual recipient/refund/payer, amount, snapshot
and settlement identity, exactly one active policy member, and pinned underlying
read evidence. A config field without this independent readback cannot fund.

Reverse approval nonce is the actor identity's independently observed initial
nonce; funding nonce is the following nonce. Actor gas must already be funded and
finalized before forward binding records the starting balance. Operator gas
setup, if ever separately approved, is outside this tool and needs its own actual
receipt/fee accounting and recaptured capital after source baseline closure.

## Explicit commands

Use the actual pinned Node24/tsx pair. A development invocation is shown below;
Root's reviewed runtime pins and helper guards must use the actual absolute paths.

```powershell
pnpm --filter @zeeswap/api exec tsx scripts/market-user-circle.mjs status CONFIG RAW_CONFIG_SHA256
```

Every invocation performs one step and exits. Available steps:

- `quote-forward`, `accept-forward`: ordinary capability/idempotency API flow.
  Capability, body and keys persist before POST; an unknown result reuses them.
  A known expired quote is first reconciled by GET and never replaced if accepted.
- `quote-reverse`, `accept-reverse`: only after actual forward source and finalized
  Base payout proofs; source is exactly one mock token from those proceeds.
- `import-forward` / `import-reverse CONFIG SHA RECOVERY_FILE RECOVERY_RAW_SHA`:
  import exactly one already accepted browser private recovery entry. This does
  not prove browser wallet signing and does not import an unreviewed quoted order.
- `bind-forward` / `bind-reverse CONFIG SHA ROOT_BINDING ROOT_BINDING_RAW_SHA`:
  bind Root's accepted membership evidence before any wallet action. The forward
  bind checks zero starting mock and records finalized initial actor gas.
- `native-prepare`, `native-recover`, `native-broadcast`, `native-receipt`:
  original-byte native source operations. Preparation and initial broadcast
  require 12–40 blocks of funding lead. Existing/unknown intent never recalculates.
- `verify-forward`: independently check finalized Paid/Transfer events and actor
  source receipt. Both original order ID and exact market output remain fixed.
- `prepare-approve`, `recover-approve`, `publish-approve`, `receipt-approve`;
  then `prepare-fund`, `recover-fund`, `publish-fund`, `receipt-fund`. Approval is
  exactly 1000000 units; canonical mined approval and exact allowance are checked
  before funding. Funding receipt must be finalized for final verification.
- `verify-circle CONFIG SHA CLOSING_PROOF CLOSING_RAW_SHA`: after native delivery
  and operator SETTLE. Root separately supplies
  `ROOT_MARKET_USER_CIRCLE_LEDGER_CLOSED`: matching policy/two IDs/four quantities,
  two settled orders, two discharged obligations, zero open reservations/leases,
  balanced ledger, no unexpected financial effects and pinned raw read evidence.
  Include actorNativeBalanceBeforeZatoshi (the approved initial capital),
  actorNativeFeeZatoshi=`10000`, and independently read
  actorNativeBalanceAfterZatoshi = initial capital - 110000 + reverse output.
  The actor independently verifies shielded incoming amount/canonical confirmations,
  finalized funding receipt, exact residual mock and actual user gas conservation.

The CLI writes private child stdout/raw receipts only to protected local files.
User-facing steps print status only. Internal `guard-*` commands emit the private
child protocol and must be connected to captured pipes, never public logs.
Missing positive owned-process cleanup preserves
the actor lock for Root investigation. No automatic deletion, raw replacement,
nonce bump, retry broadcast or authority renewal is provided. Price snapshot
expiry after acceptance does not change funding terms. New source actions still
require current own-order busy gates and unexpired Root actor authority.

## Evidence classification

`MARKET_USER_CIRCLE_RECEIPTS_VERIFIED_API_ACTOR` means actual API-actor receipt and
independent Root ledger evidence passed. It does not establish browser wallet
signing, G5 completion, a continuous 300-second readiness gate, mainnet execution
or bridge readiness. Browser-created capabilities can be restored for viewing;
genuine browser wallet signing requires an actual provider-backed signer.

No actual actor config, key generation, faucet claim, wallet startup, SDK/signing,
public quote/acceptance or transaction was performed while preparing this tooling.
